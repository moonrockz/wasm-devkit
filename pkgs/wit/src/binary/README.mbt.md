# WIT binary validation boundary

`moonrockz/wit/binary` validates type-only component encodings without executing
components or accessing files, networks or subprocesses. A `ValidatedComponent`
retains immutable bytes. It proves component validation within the documented
encoding boundary. It does not prove WIT package reconstruction or dependency
resolution. The [verifier](../verifier/README.mbt.md#encoded-dependencies) performs
those separate operations within its documented encoded-package profile.

The boundary admits component preamble version 13, layer 1, and custom, component
type and component export sections. Component/instance type declarations, aliases,
imports and exports are framed with explicit work stacks. Physical type-scope
nesting is limited to 256 before the dependency parser runs. Core declarations,
core module descriptions and other root sections return an unsupported-encoding
diagnostic. Type indices and component type semantics then validate through
the validator retained from `Milky2018/wasm_component@0.16.0` with a
[licensed accessor and instance-signature compatibility patch](validation/README.md). A further explicit-stack
pass enforces the pinned wasmparser memory64 value-layout limit, below 2^28 bytes,
including record/variant padding, fixed lists and aliases across scopes. Fixed
lists contain 1 through 1,073,741,824 elements and must also fit that byte limit.
Records, tuples, variants and enums are limited to 10,000 fields or cases.

The dependency's mutable parsed model never escapes this package. The original
`Bytes` value is immutable. `WIT-B001` reports malformed framing, encoding or UTF-8;
`WIT-B002` reports an unsupported encoding boundary; `WIT-B003` reports component
type-validation failures. Diagnostic offsets count bytes, not UTF-16 code units.
An absent offset means the dependency validator supplied no precise position.

```moon.pkg
import {
  "moonrockz/wit/binary",
} for "test"
```

```mbt check
///|
test "binary component validation is distinct from WIT package verification" {
  let bytes = b"\x00asm\x0d\x00\x01\x00"
  let component = @binary.validate_type_component(bytes).unwrap()
  assert_eq(component.bytes(), bytes)
  guard @binary.validate_type_component(b"broken", source_id="dep.wasm")
    is Err(errors) else {
    fail("malformed input accepted")
  }
  assert_eq(errors[0].source, "dep.wasm")
  assert_eq(errors[0].offset, Some(0))
  assert_eq(errors[0].code, "WIT-B001")
}
```

Tests use an original package generated by wasm-tools `1.262.0`, commit
`e22db44da4eaf17a0e46ec55b911c7539589a3cc`. They compare every truncated prefix
with the pinned component validator and exercise malformed metadata, random type
payloads and 10,000 physical type scopes on all four targets.
