# Component binary validation boundaries

`moonrockz/wit/binary` validates component metadata without executing components
or accessing files, networks or subprocesses. `validate_type_component` checks
the WIT type-only profile. A `ValidatedComponent`
retains immutable bytes. It proves component validation within the documented
encoding boundary. It does not prove WIT package reconstruction or dependency
resolution. The [verifier](../verifier/README.mbt.md#encoded-dependencies) performs
those separate operations within its documented encoded-package profile.

The boundary admits component preamble version 13, layer 1, and custom, component
type and component export sections. Component/instance type declarations, aliases,
imports and exports are framed with explicit work stacks. Physical type-scope
nesting is limited to 256 before the dependency parser runs. Core declarations,
core module descriptions, component-value externs, root export ascriptions and
other root sections return an unsupported-encoding
diagnostic. Type indices and component type semantics then validate through
the validator retained from `Milky2018/wasm_component@0.16.0` with a
[licensed accessor and instance-signature compatibility patch](validation/README.md). A further explicit-stack
pass enforces the pinned wasmparser memory64 value-layout limit, below 2^28 bytes,
including record/variant padding, fixed lists and aliases across scopes. Fixed
lists contain 1 through 1,073,741,824 elements and must also fit that byte limit.
Records, tuples, variants and enums are limited to 10,000 fields or cases.

The dependency's mutable parsed model never escapes this package. The original
`Bytes` value is immutable. `WIT-B001` reports malformed framing, encoding or UTF-8;
`WIT-B002` reports an unsupported encoding boundary; `WIT-B003` reports component
type-validation failures. Diagnostic offsets count bytes, not UTF-16 code units.
An absent offset means the dependency validator supplied no precise position.

```moon.pkg
import {
  "moonrockz/wit/binary",
} for "test"
```

```mbt check
///|
test "binary component validation is distinct from WIT package verification" {
  let bytes = b"\x00asm\x0d\x00\x01\x00"
  let component = @binary.validate_type_component(bytes).unwrap()
  assert_eq(component.bytes(), bytes)
  guard @binary.validate_type_component(b"broken", source_id="dep.wasm")
    is Err(errors) else {
    fail("malformed input accepted")
  }
  assert_eq(errors[0].source, "dep.wasm")
  assert_eq(errors[0].offset, Some(0))
  assert_eq(errors[0].code, "WIT-B001")
}
```

Tests use an original package generated by wasm-tools `1.262.0`, commit
`e22db44da4eaf17a0e46ec55b911c7539589a3cc`. They compare every truncated prefix
with the pinned component validator and exercise malformed metadata, random type
payloads and 10,000 physical type scopes on all four targets.

## Declarative package metadata

`validate_declarative_component` additionally admits root imports and component
aliases. It returns a separate `ValidatedDeclarativeComponent` with immutable
bytes. It supports imported functions, instances and components, type aliases,
and re-exports, plus declarative core module/function types and module externs.
Core instances and synchronous canonical lift/lower validate full core contracts
and canonical signatures. Imported-component instantiation and inline instances
validate complete argument contracts. Concrete nested component definitions,
non-resource runtime type arguments, runtime-produced values, async canonical
functions, other intrinsics and component start sections return `WIT-B002`. Physical type-scope nesting has the same 256 limit.
Component-value externs use a framing-guided adapter for the retained parser's
legacy descriptor tags while preserving the original bytes. Supported export annotations are described below; missing
complete contracts produce explicit unsupported diagnostics.

This entry point follows WAC 0.12.0's wasmparser 0.258.0 metadata profile. It does
not impose the newer memory64 layout bound or primitive-only map-key rule used
by the WIT type-only entry point. Map keys still require valid value types.
Both profiles check fixed-list counts and aggregate field/case limits. Package
identity and dependency lookup remain separate operations. The
[WAC verifier](../../../wac/src/verifier/README.mbt.md#declarative-component-packages)
reconstructs immutable type graphs within this declarative profile.

Both profiles permit importing and exporting own/borrow handle types when their
resource is named. An unnamed resource still makes such a type invalid.

```mbt check
///|
test "declarative validation retains a separate immutable snapshot" {
  let bytes = b"\x00asm\x0d\x00\x01\x00"
  let valid = @binary.validate_declarative_component(
    bytes,
    source_id="dep.wasm",
  ).unwrap()
  assert_eq(valid.bytes(), bytes)
}
```

The [pinned WAC dependency fixtures](fixtures/wac/README.md) cover all 49 parseable
dependency binaries from its resolution corpus. One invalid WAT fixture is
retained with an explicit exclusion. Original probes check re-export behavior,
nested aliases, malformed metadata, truncation, random sections and deep scopes.

The declarative profile accepts root function-export ascriptions when the function
has a complete retained signature. An explicit work stack compares parameter
names, async mode, structural values and nominal resources. Instance-exported
function aliases retain complete reachable type graphs and defining scopes.
Nested imported instances retain complete signatures, nominal resource binders
and exported value-type aliases in private indexed graphs. Type-equality export
ascriptions compare complete structural shapes and nominal resource identities,
including aliases and re-exports. Instance annotations check functions, values,
nominal resources, nested instances/components and core modules against the complete
expected contract. Annotated aliases and re-exports
retain the narrowed contract. The type-only WIT entry point continues to reject all
root export ascriptions. Runtime-produced component values and concrete runtime component definitions remain unsupported.
Section 5 supports imported-component instantiation and inline instances, with
complete argument contracts and nominal resource substitution. Non-resource type
arguments remain unsupported until named-type origins are retained.

Core declarations have separate lexical index validation and retain complete
unsigned signatures through `moonrockz/wit/core_types`. Concrete GC/shared heap
references and recursive groups remain unsupported. Nested core declarations
with limits above u32 or custom memory pages return `WIT-B002` before the pinned
parser runs; root core-type sections support those encodings.


The declarative entry point also validates flat concrete core modules. The
`core_types.inspect_module` preflight retains full contracts and charges a
conservative work estimate before the original bytes reach the core validator.
The sum across modules is limited to 1,000,000. Structured instructions,
concrete/shared heap references, supertypes and shared globals reject before
recursive parsing. Function-only groups without recursive references are valid.
The type-only WIT entry point continues to reject concrete core modules.

Core module export annotations use the ordered lexical module/type bindings and
check complete module contracts. Imports are contravariant, exports covariant;
unsigned limits, shared flags, table width and custom page sizes are preserved.
Later reexports see the annotated contract. Comparison work is bounded across
all annotations. The 49 retained cases compare binary and WAT package models;
three version differences are recorded in `tests/semantic/wac-module-ascriptions`.

Imported component export annotations compare complete scoped contracts,
including nested instance/component contracts and core modules. Imports are
contravariant and exports covariant. Resource binders use directed substitution;
captured resources and equality constraints remain nominal. Explicit work stacks
and cumulative budgets cover extraction and comparison. Annotated re-exports
retain their narrowed contract. Component aliases extracted from imported
instances retain complete scoped metadata and captured resource identities.


Canonical `resource.new`, `resource.drop` and `resource.rep` validate resource
identity and retain complete core signatures. New/rep require local resources;
drop also accepts imported resources. Representation types may be i32 or i64,
while resource handles remain i32. Destructors must accept exactly the resource
representation and return nothing. Export aliases preserve the original local
identity. The 42 cases in `tests/semantic/wac-resource-intrinsics` compare both
pinned validators and full binary/WAT models; four emitted compositions validate.

## Declarative component values

The WAC profile validates value imports, exports, imported-instance aliases and
annotations, including exact one-use rules and complete named/nominal types.
Its wasmparser 0.258 rules permit borrowed value exports. Type-only WIT inputs
continue to reject value externs. `ValidatedDeclarativeComponent.bytes()` retains
the original input; `parser_bytes()` provides the immutable compatibility encoding
for the retained parser. Only framing-identified value descriptors and their section
lengths change. Core bodies, custom sections and unrelated bytes remain exact.
